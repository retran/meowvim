1. INTRODUCTION                                       *meowvim* *meowvim-introduction*

meowvim is a Neovim configuration for Neovim 0.12 or later. It loads 17
plugins at startup and installs the rest on demand.

Your settings live in one Lua table at `~/.config/meowvim/config.lua`. The
repository holds the plugin specs, that file holds your choices, and a watcher
reloads it when you save.

The pieces you interact with most:

    snacks.nvim     picker, explorer, dashboard, scratch, terminal
    blink.cmp       completion
    vim.lsp         17 servers, each started when its binary is present
    treesitter      27 parsers on top of the 7 Neovim ships
    conform         formatting
    nvim-lint       linting
    gitsigns        hunks, with LazyGit and Neogit for the rest

External tools are optional. meowvim checks for each one before using it, so a
missing tool costs you that feature and nothing else.

2. QUICK START                                          *meowvim-quickstart*

Requirements: Neovim 0.12 or later, Git, a true-color terminal, and a Nerd
Font for the icons.

Install: >
    mv ~/.config/nvim ~/.config/nvim.backup
    git clone https://github.com/retran/meowvim.git ~/.config/nvim
    nvim
<
lazy.nvim bootstraps on the first run and installs the plugins. Treesitter
then compiles its parsers in the background.

Check the result with |:checkhealth| meowvim.

Press <leader> (space) and wait: which-key lists the groups. `<leader>hk`
searches every mapping by name.

3. CONFIGURATION                                     *meowvim-configuration*

meowvim writes `~/.config/meowvim/config.lua` on the first run and reloads it
when you save. Options you leave out keep their defaults: >

    return {
      core = { theme = "catppuccin", variant = "mocha" },
      editor = { tabstop = 2, indent = 2 },
      ui = { transparency = 0 },
    }
<
Sections and the options each one holds:

    core        theme, variant, leader_key, enable_copilot, update_check,
                day_night_mode, day_theme, day_variant, night_theme,
                night_variant
    editor      tabstop, indent, expand_tabs, line_numbers,
                relative_numbers, wrap, auto_save, format_on_save
    ui          transparency, winbar, cmdheight, pumheight, icons
    performance buffer_auto_close, buffer_threshold, startup_dashboard
    lsp         diagnostics.virtual_text, .signs, .underline,
                .update_in_insert
    formatting  formatters, timeout_ms
    linting     auto_lint, linters
    git         enable_signs, blame_line, show_deleted, lazygit_theme_sync
    sessions    auto_save, auto_restore, per_branch
    snacks      image_preview, scope_highlighting, custom_styles,
                dashboard.show_projects
    toggles     the runtime switches under <leader>o
    plugins     free-form table for your own plugin settings
    custom      free-form table for anything else

`docs/02-CONFIGURATION.md` in the repository lists every option with its type,
default, and range.

Reading the configuration from your own Lua: >

    local config = require("meowvim.config")
    local theme = config.get("core.theme", "catppuccin")
<
`config.get()` returns the default only when the key is absent, so an option
set to `false` comes back as `false`.

4. PROJECTS                                               *meowvim-projects*

`~/.config/meowvim/projects.lua` gives a directory its own theme and a command
to run when you open it: >

    return {
      work = {
        path = "~/work",
        theme = "tokyonight",
        variant = "night",
        on_open = "Neogit",
      },
    }
<
`path` is required and expands `~` and environment variables. `theme` and
`variant` override the `core` section, `on_open` runs after the session loads,
and `inherit = false` stops the project from overriding the base theme.

meowvim matches the working directory against each `path` and applies the
first project that contains it. The paths also feed the `<leader>fp` picker.

6. KEYMAPS                                                 *meowvim-keymaps*

The leader is space. Press it and wait for which-key, or search every mapping
with `<leader>hk`.

Groups:

    <leader>f   files                <leader>b   buffers
    <leader>s   search               <leader>j   jump
    <leader>w   windows              <leader>n   navigate (LSP)
    <leader>c   code                 <leader>g   git
    <leader>t   tests                <leader>d   debug
    <leader>x   tasks                <leader>r   review
    <leader>y   yank                 <leader>u   history
    <leader>N   notes                <leader>o   options
    <leader>q   quit and sessions    <leader>h   help
    <leader>S   swap parameters

The ones worth learning first:

    <leader>ff  find a file          <leader>s/  grep the project
    <leader>bb  switch buffer        <leader>gg  LazyGit
    <leader>cc  code action          <leader>cr  rename symbol
    <leader>cf  format               <leader>nd  go to definition
    <leader><space>  jump anywhere   F2          terminal

Motions between things use bracket pairs: `]h` and `[h` for hunks, `]d` and
`[d` for diagnostics, `]x` and `[x` for conflicts, `]w` and `[w` for
references, `]r` and `[r` for review comments, `]b` and `[b` for buffers.

`docs/KEYMAPS.md` in the repository lists every mapping.

7. TOGGLES                                                 *meowvim-toggles*

The runtime switches under `<leader>o`:

    <leader>ow  wrap                 <leader>os  spell
    <leader>on  line number mode     <leader>oc  cursorline
    <leader>ol  whitespace           <leader>oh  search highlight
    <leader>oe  sign column          <leader>og  indent guides
    <leader>od  dim inactive         <leader>ox  diagnostics
    <leader>oi  inlay hints          <leader>ot  linting
    <leader>of  format on save       <leader>oa  auto-save
    <leader>oC  Copilot

`<leader>op` writes the current state of all of them into
`~/.config/meowvim/config.lua`, so the next start begins where you left off.

8. THEMES                                                   *meowvim-themes*

17 colorschemes ship with meowvim, and only the active one loads at startup.
The rest are installed but idle, so switching costs a load and not a download.

    catppuccin  tokyonight  rose-pine   gruvbox     nord
    kanagawa    everforest  nightfox    zenbones    solarized-osaka
    ayu         dracula     monokai-pro onedark     material
    melange     github

`<leader>ok` opens the theme menu: a day theme, a night theme, the mode, and
the ready-made pairs. In `auto` mode meowvim follows the system appearance and
switches when the system does; the probe runs outside the editor loop, so it
never blocks typing. `<leader>oK` switches by hand and puts the mode into
`manual`.

9. TROUBLESHOOTING                                  *meowvim-troubleshooting*

Run |:checkhealth| meowvim first. It reports Neovim's version, whether the
configuration loads and validates, which external tools it found, the mise
tools for the current project, the plugin and parser counts, and the language
servers on your PATH.

Settings have no effect:
    Run |:MeowvimConfigValidate|. It names any option whose type or range is
    wrong, and stays silent about an option the schema does not know, so check
    the spelling. |:MeowvimConfigShow| prints what meowvim actually read.

No language server attaches:
    meowvim starts a server only when its binary is on PATH. Use
    `:checkhealth vim.lsp` for the live clients; `:LspInfo` was removed in
    nvim-lspconfig 2.

Formatting or linting does nothing:
    `:ConformInfo` and |:LintInfo| list the tools for the filetype and mark
    which ones resolve. Names differ from binaries: `golangcilint` runs
    `golangci-lint`, `ruff_format` runs `ruff`.

No syntax highlighting:
    meowvim starts treesitter for any filetype with an installed parser.
    `:TSInstall {language}` adds one. A very large file has its filetype set
    to `bigfile` on purpose, which turns highlighting off.

Icons are boxes:
    Select a Nerd Font in the terminal, or set `ui.icons = false`.

Slow startup:
    `<leader>oPl` lists the plugins by load time and `<leader>oPt` compares
    the last 100 starts.

`docs/04-TROUBLESHOOTING.md` in the repository covers more cases.
